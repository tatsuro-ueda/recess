# 機能の決めごと

判定の表と状態遷移の正本は [spec.md](spec.md)（決定 2026-10-23）。ここは、その表から決まることだけを書く。

## 2つの大きな状態

| 状態 | 意味 | 判定 |
| --- | --- | --- |
| foreground | 人の手が要る | 印が `to be read` か `reading` のペインがある |
| background | 人の手が要らない | それ以外（印が `working` か `read` か、印なし） |

画面を動かすのは、この2つの**間を移るとき**だけ。background の中で状態が変わっても動かさない。

## 連れ出す条件（すべて満たすとき）

1. foreground → background へ移った
2. その瞬間、最前面が**帰り先**だった
3. どこかに `working` がある（待つ相手がいる）
4. 手を離して一定秒数
5. 直前の呼び戻しから一定秒数が過ぎている

読み中は 1 の foreground に含まれるので、ここで重ねて見ない。

「読み終えたか」は判定しない。読み終えたら、人が自分でブラウザへ移る（2026-10-23 ユーザー判断「読み終わったときは自分でブラウザに移動すればいい」）。判定しようとすると、時間・文字数・スクロール・キー操作のどれも、外れたときに読んでいる最中の人を連れ出すため。

## 帰り先

「そこにいる人を休憩へ連れ出してよい場所」。ターミナルは常に帰り先。エディタは、**その中で動くAIが生きているときだけ**帰り先になる（手で編集しているだけの人を連れ出さないため）。

## 呼び戻す条件

- 印が新しく `to be read` になったペインがある（前の周にもいたペインだけを数える）
- **呼び戻しで画面を動かすのは、ブラウザを見ているときだけ。** それ以外は理由を1行残して何もしない

## ジャンプ

この Mac のペインの印が新しく `to be read` になったら、そのペインまで移る。手を離して一定秒数以上、かつ SSH ログインが無いときだけ。区画を持たない状態源（エディタの中のAIなど）へは移れないので、アプリを前に出すところまでで止める。

## 画面の印

サイドバーに出す印は4つ。herdr から見ると `reading` も `read` も「ただの `idle`」なので、区別を持てるのは recess 側だけ。印の決め方は spec.md の表がすべてで、連れ出し・呼び戻し・`recess status` も同じ印を読む。

| herdr の状態 | 印 | 意味 |
| --- | --- | --- |
| `done` / `blocked` | `to be read` | 次に読むもの（人が読んで答える） |
| `working` | `working`（`$recess_working` を置いたときだけ） | 待つ相手 |
| `idle`（今見ている） | `reading` | いま読んでいる場所。常に1つだけ |
| `idle`（終わってからまだ見ていない） | `to be read` | herdr が `done` を飛ばした完了 |
| `idle`（それ以外） | `read` | もう読み終わっている |

覚えておくのは「終わってから、まだ見ていないペイン」だけで、ほかは毎周その場で決める。

印は他マシンのペインにも出す。応答しない端末は、30秒は前回の状態で判定に使い、過ぎたら表から外す。応答しないあいだは印を書きにも消しにも行かない（ssh を投げ続けない。印は TTL で消える）。戻ったときに to be read が残っていれば呼び戻す。

### 色

既定では同じトークン（`$recess`）に入るので同じ色になる。意味ごとに色を変えたいときは、herdr のサイドバー行へ `$recess_now`（reading）・`$recess_done`（read）・`$recess_working`（working）を足す。recess は設定を見て書き分け、置かれていないトークンは `$recess` へ落とす（設定を触っていない人の印が消えないように）。ただし working だけは落とさず出さない（作業中の行が to be read と同じ赤になるため）。

**herdr は起動時にしか設定を読まない。** 動かしたまま行を差し替えても効かず、recess だけが新しいトークンへ書くので画面から印が消える（2026-10-14 に実測）。差し替えは herdr を立て直すときに行う。

## 記録

`~/.local/state/recess/watch.log`。1行1出来事で、**見送ったときも理由を1行残す。**

現在地は `~/.local/state/recess/status.json`。毎周上書きし、`recess status` が読んで並べるだけにする。**判定を status 側に書かない**（2か所に置くとずれて、妨げている理由を間違えて教える）。

作法は `docs/ux-policy.md`「記録の作法」が正本（全行がタグから始まる／タグ一覧は1か所／3階層／差は1軸だけ）。

**実装は、まだこの作法に届いていない。** 2026-10-04 の実測で行頭は14種類あり、6文字幅に揃えかけて途中でやめた跡が残っている（`WAKE` は2スペース、`LABEL` は1スペース、`state:` はコロン、`no jump:` と `front app is` は文章がそのまま始まる）。**直すのは実装のほうで、この文書を実装へ合わせて緩めない。**1本化は別タスクで行う。

## 設定

すべて環境変数（`RECESS_` で始まる）。数値が壊れていたら既定へ戻し、起動は止めない。一覧は `docs/spec.md`。
