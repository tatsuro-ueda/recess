# UX 方針

Recess は人の画面を勝手に動かす道具なので、「どう動かすか」より先に「動かしてよいか」を決める。
この文書は、画面を動かす側の作法と、知らせ方・記録の物差しを持つ。

## 最上位の約束：いつでも1手でやめられる

画面を奪う道具だから、これが物差しの最上位に来る。

- `recess off` の1手で、状態は追うが画面は動かない状態にできる
- 予告が出ているあいだは、**手を動かすだけで中止**できる（覚える操作を増やさない）
- やめる手段を増やす機能追加は歓迎するが、**やめる手段を1手より深くする変更は入れない**

## 共通の物差し（具体値）

画面に関わる数値は、この表の値を使う。似た値を場面ごとに新設しない。

| 物差し | 値 | 理由 |
| --- | --- | --- |
| 見回りの間隔 | 2秒 | これより短いと常駐の負荷が目に見え、長いと呼ばれた気づきが遅れる |
| 手を離したとみなす時間 | 3秒 | 打鍵の切れ目ではなく「離席した」と言える最短 |
| 予告を読む時間 | 5秒 | 通知を読んで、やめる判断をして、キーに手を戻せる長さ |
| 呼び戻し後に動かさない時間 | 0秒（必要なら5秒） | 続けて聞かれることが多いので、既定では待たない |
| 送るキー | スペース1回だけ | 再生状態を読めないので、増やすと必ずずれる |
| 画面に出す印 | 常に1つだけ | 読む人は1人しかいない。3つ出ると、どれを読んでいるか分からなくなる |
| 通知の種類 | 1出来事につき1本 | 同じ結果を言い分けない（下の「知らせ方」を参照） |

## 画面を動かしてよいか

1. **動かすのは、状態が大きく変わる瞬間だけ。** 同じ状態の中の小さな変化では動かさない
2. **連れ出すのは、帰り先にいる人だけ。** ほかのウィンドウで作業している人は休憩中ではない
3. **呼び戻すのは、動画を見ている人だけ。** 会議や別のアプリの最中に画面を奪わない
4. **見送ったときは、必ず理由を1行残す。** 「動かなかった」と「動けなかった」を後から分けられるようにする
5. **印を覚えて後で動かさない。** 見送った回はその場で捨てる。帰り先へ戻った瞬間に連れ出されるのは、予告のない移動と同じ

## 知らせ方

1. **動く前に知らせる。** 動いてから出した通知は、もう画面にいない人には読めない
2. **予告には、やめ方を一緒に書く。** 「手を動かせば中止」は見た目から絶対に推測できない。説明を1つだけ賭けるならここ
3. **やめたことも知らせる。** 予告を読んだ人が「結局どうなったのか」を確かめに行かなくて済む
4. **人がやめさせたなら、そう書く。** 受け身で書かない（「中止されました」ではなく「やめました」）
5. **できなかったことは1本で知らせる。** 失敗のしかたを言い分けない。使う人がやることは「自分で動かす」の1つだけで、どこで失敗したかは**ログの役目**
6. 通知の文は、**何が起きるか / 何が起きたか**だけを書く。内部の言葉（focus など）を混ぜない

## 記録の作法

人が探すのは「画面が動いたか」。それが埋もれない形にする。

1. **全行がタグから始まる。** 文章がそのまま始まる行を作らない
2. **タグの一覧は1か所に持つ。** 一覧に無いタグで記録しようとしたら落ちるようにする（文章で書いただけの作法は守られない）
3. **3階層に分ける。** 動いた（画面が実際に変わった） / 決めた（動かすか判断した） / 見ていた（背景）
4. **階層の差は1軸だけで示す。** テキストに太さは無いので、2軸使うと階層ではなく霧になる
5. 1行1出来事。状態の要約は変わったときだけ書く
6. 判断に使った数値（手を離した秒数、最前面のアプリ）を同じ行に残す。後から集計できる形にする
