# 設計判断

なぜこの形なのか。変えるときは、ここに書いた理由ごと更新する。

## 3つの部品

| 部品 | 役目 | 置き場 |
| --- | --- | --- |
| 常駐（python3） | 状態を集めて判断し、画面を動かす指示を出す | `~/.local/share/recess/` |
| キーを送る小アプリ | スペースキーを1回送る。中身は1行 | `~/Applications/Recess.app` |
| 切り替えの CLI | ON / OFF / 状態表示 | `~/.local/bin/recess` |

## 権限をアプリ1つに閉じ込める

**判断**：キーを送るのは小アプリだけ。常駐の python3 には許可を出さない。

**理由**：アクセシビリティ許可は「画面上の何でも操作できる」強い許可。常駐は数百行あり、他マシンへ ssh もする。そこへ強い許可を与えたくない。小アプリは1行なので、中身を目で確かめられる。

**帰結**：常駐が使えるのは権限の要らない道具だけ（`open` `lsappinfo` `caffeinate` `ioreg` `who`）。`osascript` は使わない。

## 状態は「集めて、差分で見る」

**判断**：一定間隔で全ペインの状態を集め、前回との差分で判断する。イベントを待ち受けない。

**理由**：状態の出どころが複数ある（この Mac、他マシン、エディタの中）。それぞれが別のやり方で知らせてくるので、受け口を増やすより、集める側を1つにしたほうが判定が1か所で済む。

**帰結**：見回りの間隔より短く終わるやり取りは見えない。これは受け入れる。

## 状態源は足せる形にする

**判断**：状態の出どころを herdr に限らず、**同じ形に揃えてから1つの列に並べる**。

**理由**：エディタの中で動くAIは、ターミナルの区画を持たないので herdr から見えない。判定のしかたは同じでよいので、入口だけ増やす。

**帰結**：判定の本体は状態源を知らない。増えた源が黙っても、他の源の判断は続く。源ごとに「できない操作」がある（区画を持たない源へは移動を指示できない）ので、操作は源を見て選ぶ。
